# 새 센터에 까는 순서 (뼈대)

> 초안 — 문장은 나중에 다듬는다. 순서와 빠뜨리면 안 되는 것만 적었다.

## 1. DB 만들기

- 둘 중 하나.
  - Supabase 프로젝트(서울 리전) — REST 로 붙는다.
  - PostgreSQL 17(예: Azure Database for PostgreSQL, Korea South) — 주소로 직접 붙는다.
- 빈 DB에서 시작한다. 씨앗 데이터는 필요 없다(설정 기본값은 마이그레이션이 넣는다).

## 2. 마이그레이션 001~034 실행

- `db/sql/` 의 파일을 **번호 순서대로** 실행한다(Supabase는 SQL Editor, PostgreSQL은 `psql -f`).
- 이름에 `_check` 가 붙은 파일과 `008_check_anon_access.sql` 은 **진단용(읽기만)** 이다 — 실행해도 되지만 바꾸는 것이 없다.
- 같은 번호에 두 파일이 있으면(031·032·034) 진단(`_check`)이 아닌 쪽이 실제 변경이다.
- 확인: 표 15개 안팎이 생기고 `staff`·`children_identity` 는 0건, `settings` 에 기본값 몇 줄.
- (PostgreSQL 직결이면) 마이그레이션 전에 역할 세 개를 만든다 — 027·030 의 `grant ... to service_role` 이 이 역할을 가리킨다.
  ```sql
  do $ begin
    if not exists (select 1 from pg_roles where rolname = 'anon') then create role anon nologin; end if;
    if not exists (select 1 from pg_roles where rolname = 'authenticated') then create role authenticated nologin; end if;
    if not exists (select 1 from pg_roles where rolname = 'service_role') then create role service_role nologin; end if;
  end $;
  ```
  (Supabase 는 이 역할들이 처음부터 있어 그냥 넘어간다.)

## 3. 환경변수

| 이름 | 필수 | 설명 |
|---|---|---|
| `DATABASE_URL` | 둘 중 하나 | PostgreSQL 직결 주소. 있으면 Supabase 키는 쓰지 않는다 |
| `SUPABASE_URL`·`SUPABASE_KEY` | 둘 중 하나 | Supabase 주소와 service_role 키(서버 전용) |
| `AUTH_ENFORCE` | ✅ | `true` — 로그인 잠금. 처음부터 켠 채로 설치한다(아래 5 참고). 비워 두면 첫 관리자를 정하는 순간 잠긴다. `warn` 은 비상 되돌리기(막지 않고 기록만) |
| `ANTHROPIC_API_KEY` | ✅ | 일지 분석(AI) |
| `NLK_API_KEY` | 권장 | 국립중앙도서관 ISBN 조회 |
| `DATA4LIBRARY_API_KEY` | 선택 | 도서관 정보나루 검색 |
| `PORT` | 선택 | 기본 8000(Deno Deploy 에서는 두지 않는다) |
| `ANALYSIS_SWEEP` | 컨테이너(지금 운영) | `interval` — 미분석 일지 안전망. Deno Deploy 에서는 Deno.cron 이 자동이라 두지 않는다 |
| `DATABASE_POOL_MAX` | 선택 | 직결 연결 수 상한 |

- 키는 코드·프론트에 두지 않는다(CLAUDE.md 원칙 3).
- 배포 방법: Deno Deploy(`main.ts`) — 이 데모가 그렇게 돈다.

## 4. 접속

- `https://<주소>/health` → `database : OK`
- `https://<주소>/` → 로그인 화면으로 간다(잠금 켜짐).

## 5. 첫 종사자·관리자 등록

- 명단이 비어 있으면 로그인 화면이 **"첫 관리자를 정합니다 — 첫 종사자 등록"** 을 보여 준다.
  - 이름·직급(센터장 / 생활복지사) → 비밀번호 두 번 → [관리자로 시작].
  - 그 사람이 명단에 등록되고(감사 로그 "최초 부팅") 관리자가 된다. 로그인 이름 = 입력한 이름.
- 명단에 이미 센터장·생활복지사가 있으면(자료를 옮겨 온 경우) 그중에서 고른다.
- 이 화면은 **한 번만** 열린다 — 부팅 표시(`bootstrap_done`)가 생기거나 비밀번호 계정이 하나라도 있으면 닫힌다(409).
- 처음 들어가면 개인정보 처리 동의를 한 번 묻는다.

## 6. 센터 설정

- [설정 › 동의서] 센터 이름·동의서·처리방침 문구(보관처가 실제 DB 위치와 맞는지).
- [설정 › 관찰 영역]·[설정 › 봉사자 설정] 필요하면.
- (선택) 두 번째 관리자 — [설정 › 계정 관리 › ⋯ › 관리자로].

### 종사자에게 알릴 것 — 이름 적는 법

- **일지·관찰에는 명단에 등록된 표기 그대로 이름을 적는다.** 가명화는 등록된 이름을 기준으로 가리기 때문에,
  명단에 없는 별명("마이키", "쭈꾸")으로만 적으면 그 표기는 가려지지 않은 채 분석에 나간다.
- 긴 이름·외국계 이름은 뒤쪽 두·세 글자로 불러도 가려진다("응우옌티마이" → "마이"), 띄어쓰기가 달라도 같은 이름으로 본다.
- 별명을 꼭 써야 하면 아동 이름을 그 별명으로 등록하거나, 일지에는 등록 이름을 함께 적는다.
